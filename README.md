# OA Sales Coach Ver.1

スマートフォンから接客直後に記録し、学習・振り返り・月間分析に使うWebアプリです。PCでも表示できます。

## 公開状況と開き方

現在はGitHub Pages公開前の準備版です。公開URLはまだ確定していません。
公開後は専用リポジトリの Settings → Pages に表示されるHTTPSのURLを開いてください。
URLの形式は `https://<アカウント名>.github.io/<専用リポジトリ名>/` です（この表記は例で、アクセス先ではありません）。

公開後はPC・開発サーバー・テザリングを起動する必要はありません。スマートフォンのインターネット接続は必要です。オフライン起動は保証していません。いつも同じブラウザの通常モードで同じHTTPSのURLを開き、ブックマークしてください。

## 完成している機能

- ホーム、勤務記録、接客の簡易登録と詳細入力・編集、複数商品の記録。
- 接客結果6分類：Panasonic成約／他社成約／購入見送り／検討・持ち帰り／商品説明のみ／結果不明。
- Panasonic提案有無と店舗スタッフ引継ぎ有無を、結果と別に記録。他社メーカー・型番、理由と改善できる要因・外的要因・未分類も記録。
- 学習課題：接客との関連付け、優先度、未着手・学習中・解決済み、学んだ内容と次回試すこと。
- 1日の振り返り：勤務・接客の自動集計と短い振り返り。
- 月間ダッシュボード：勤務、接客、提案、引継ぎ、結果、カテゴリー・型番・メーカー・理由・要因別集計と学習課題の状態。
- 過去の接客の条件検索と編集。
- 勤務・接客・商品明細・学習課題・振り返りの5種類のCSV出力。
- 全期間の記録と設定のJSONバックアップ、復元前の検証と件数確認。

## 毎日の入力

1. 勤務日と店舗の識別名を登録します。時間集計には開始・終了時刻と休憩も入力してください。
2. 「＋ 接客を記録」でカテゴリー・提案有無・結果を選び、必要なら引継ぎありにして保存します。
3. 型番や理由などは後から追記できます。接客日と勤務との関連付けも確認してください。
4. 疑問は学習課題へ、終業時には1日の振り返りを記録します。
5. 終業時にJSONバックアップを保存します。

入力途中の自動保存はありません。保存完了を確認してください。音声入力はスマートフォンのキーボードのマイクを利用します。個人名・連絡先・非公開の顧客情報は入力しないでください。

## 集計について

接客日を基準に月を判定します。後日結果を変更すると元の接客月の集計が変わります。複数商品でも接客は1件です。提案・引継ぎ・最終結果は別指標で、引継ぎは必須工程ではありません。

- 提案率＝Panasonic提案件数 ÷ 全接客件数 × 100。
- 成約率（全接客）＝Panasonic成約件数 ÷ 全接客件数 × 100。
- 提案からの成約率＝提案あり、かつPanasonic成約の件数 ÷ Panasonic提案件数 × 100。

分母が0件なら「—」です。詳しい数え方はダッシュボードの「集計式と数え方」と各表の説明に表示しています。カテゴリー別の成約はPanasonic成約接客に含まれるカテゴリーで、個々の商品の成約を断定しません。型番別は購入型番の接客件数で、販売台数ではありません。学習課題は選択月に作成した課題の現在の状態です。

## データの保存先

記録は、この端末・このブラウザのlocalStorageに保存します。保存キーは `oa-sales-coach.v1` です。アプリには記録をGitHubへ送信する処理はなく、GitHub Pagesへの公開で記録が自動共有されることもありません。GitHubはサイトへのアクセス情報を処理しますが、アプリの接客記録を保存する仕組みとは別です。

PCとスマートフォンのデータは別々です。ブラウザのサイトデータ削除や端末故障で失われる可能性があるため、定期的にJSONを別の安全な場所にも保管してください。

保存場所は通信方式・ドメイン・ポート単位です。旧ローカルURLと公開HTTPSのURLは別の保存場所になります。同じGitHub Pagesドメイン内ではフォルダ名が違っても保存場所を共有するため、同じ保存キーを使う別版を同一ドメインに配置しないでください。

## CSVとバックアップ

「CSV・バックアップ」から対象月（または全期間）と記録の種類を選ぶとCSVを保存できます。日本語がExcelで文字化けしにくいUTF-8 BOM付きです。型番が日付などに変換される場合は、Excel取り込み時に列を文字列として指定してください。CSVは分析用で、復元には使いません。

「JSONバックアップを保存」で全期間のデータと設定を保存します。端末の「ファイル」や「ダウンロード」で保存を確認してください。バックアップJSONやCSVをこのリポジトリへ追加しないでください。

## 旧URLの記録を引き継ぐ場合

自動移行はありません。まず旧URLを使用していたスマートフォンのブラウザからJSONを保存します。公開後の新しいURLでは、JSONを選択し、検証結果と件数を確認してから、現在データの退避・最終確認を経て復元します。新しいURLで日々の入力を始める前に移行してください。

復元は新URL側の全データを置き換える操作で、追加・結合ではありません。旧URL側の記録はそのまま残ります。復元直前の退避は1世代分で、ファイルのバックアップの代わりにはなりません。今回の公開準備では復元を実行していません。

## 公開担当者向け

このフォルダの内容だけを、OA Sales Coach専用リポジトリのルートに配置する想定です。親フォルダや元の開発フォルダは登録しないでください。利用者が公開ファイル一覧を確認するまではpush・Pages公開設定を行いません。

承認後の公開方式は、専用リポジトリの Settings → Pages → Deploy from a branch → main / (root) を想定しています。HTTPSを有効にし、表示された正式URLをこの説明書に記載します。アカウント名・リポジトリ名は未確定です。

`.nojekyll` はファイルをそのまま配信する設定、`.gitignore` は確認済みのファイル以外を通常のGit追加対象から外す設定です。強制追加では回避できるため、送信直前にもファイル一覧の確認が必要です。ブラウザの手動アップロードには.gitignoreは適用されません。

公開用index.htmlにCSP（読み込めるスクリプトや通信先の制限）と参照元情報を送らない設定を追加しています。外部スクリプト・外部通信・フォーム送信を許可しません。meta形式のCSPはすべてのHTTPヘッダーを代替するものではなく、frame-ancestorsによる埋め込み防止などは含みません。ログイン・アクセス制限・保存データの暗号化を追加する設定ではありません。

公開前に、公開候補に業務資料・記録・ログがないことを確認してください。公開後はスマートフォンで表示・保存・再読み込み・CSVとJSONのダウンロードを確認します。実データを入れ替える復元テストは行いません。公開ページとソースコードは閲覧可能になる前提です。
